# Native Etas migration — in progress

The shipping `scripts/nomo` entry still uses the existing Python project controller. The opt-in `native_project` flow is the migration implementation, not a completed replacement.

## Current native path

`NativeCoding` registers real Etas `tool` declarations through `@tools`. Etas dispatches each tool body, calls its native Host boundary, and continues inference with the tool result. The native probe invokes the Etas binary directly; Python supplies only a local synthetic HTTP model, terminal transport and fixture setup/assertions.

| `git_diff` | `staged: bool`, `paths: Array<string>`; `CommandOutput` | Same native command boundary | Exact argv preview and Host approval; unstaged diff accepted on 0.12.1, staged diff still awaiting acceptance |

| `replace_file` | `change: {path, before, after}`; `FileOutcome {path, status, edit}` | Shared native edit journal, filesystem reads/listing/atomic replacement, Command and Memory | Exact original check, complete write preview and separate native Host approvals for snapshots/write |

The `ScopedReplace` trace spec permits reads, listing, atomic replacement and the native command actions needed by the shared journal; it forbids `Fs.write<ProjectRoot>`. The runtime requires human approval for every atomic replacement and command. Snapshots, directory operations and restoration use trusted-unconfined Unix utilities through the checked Command Host, not a Python dispatcher or an unapproved filesystem helper. Each command's actual argv is previewed before its runtime approval. This is not a filesystem compare-and-swap guarantee against external writers.

The approval gate is currently **not accepted** for these command paths. The executed positive flow prompted separately for every command, but its actual CommandRequest/trace omitted the just-obtained approval from the authority snapshot. This is the observed consistency bug etas-interpreter#102, not evidence of a prompt bypass. The tests retain a fresh-approval audit, comparing the dispatch snapshot with its own preceding approval rather than assuming a global count of one.

## Native file journals

All file mutation entry points, including the earlier `replace_file` and `edit_file`, now delegate to `mutations.apply_plan`. Etas owns path checks, missing-parent steps, snapshots, ordered application, result publication, journal selection, undo and explicit rollback. Journal metadata uses a separate native Memory region. Native `cp -a` snapshots live under `/native-state/edits/EDIT/`; binary contents, directory trees and Unix file modes are retained. Conversation export preserves the logical operation history, but does not transfer or activate these local undo backups.

A step's recovery material is stored before project mutation, and its phase changes to `applying` immediately before dispatch. Incomplete/failed work keeps the original conversation's pending request; internal commands record operation/result events under that owner rather than replacing it. A new mutating tool cannot overwrite the pending ticket, and completion must match its owner. Read-only file/navigation inspection records observations without clearing the ticket.

`/edits`, `/read FILE`, `/undo [EDIT]` and `/rollback EDIT` are Etas commands. Rollback walks unfinished steps backward after fresh native approval and never replays the original forward request. A completed batch and undo restored text, binary files, a directory tree and mode `0751`. A separate real Ctrl-C run stopped after a file was published and before its after-snapshot copy was approved; a new Etas process listed the journal, read the actual file without losing the pending ticket, and rolled back the partial batch. That recovery used no additional model request.

`/recover EDIT` and the native `reconcile_changes` tool settle a completed journal without replaying project operations. A previously published complete result is retained when its pending slot is cleared; result publication is idempotent across process restart. Versioned file plans interrupted before journal insertion can be classified as undispatched. Older complete, unjournalled requests retain an unknown outcome. Interrupted undo before journal ownership changes leaves the original edit applied; unfinished claimed journals still require explicit rollback. The reconciliation tool has only native Memory effects.

These are process-restart observations, not proof of every interruption window. Generic model/command failure recovery and interrupted import/fork handling still need work. A batch has per-operation approvals and a retained partial state; it does not have a single atomic filesystem commit. The authority audit still fails on upstream #102, so the feature's full approval acceptance is incomplete.

## Native conversations and context

`ConversationStore` / `NativeHistory` use the Etas Memory Host with SQLite at `/native-state/conversations.sqlite3`. Etas owns session creation, selection, listing, renaming, user/assistant messages, tool requests/results, summaries and the ledger. A source `SessionContext` effect binds tool logging to the selected conversation; the entry handles it inside the model call. There is no Python conversation or SQLite adapter in this path.

Events are append-only records with separate content chunks. The 65,536-scalar chunk width keeps individual Memory values below the upstream storage limit; it is not a task, message or conversation length limit. Large-event acceptance is blocked by the native string-slice continuation hang reported in etas-interpreter#101; no slicing workaround is used. Event indexes are reserved before publication. An interrupted archive write appears as an explicit incomplete record, and a tool is not dispatched until its request record is saved. Pending requests survive process exit and are shown on startup; complete interruption/recovery handling remains a separate unfinished gate.

`RollingContext` keeps the original request, a model-generated summary and recent original events. After summarization, the recent suffix has at most 12 events and 393,216 text bytes; larger events remain in the archive and are represented by the summary. This recent-suffix change has not passed large-event acceptance because of #101. The automatic trigger uses a text estimate of three UTF-8 bytes per token at 75% of the configured 1,048,576-token window. `/compact` uses the native summary agent; it never deletes original events. The ledger records attempted agent turns, tool requests, compactions, configured generation allowances and estimated context bytes. These counters are not measured provider token usage or billing.

The native entry requires `--workspace PATH` identifying the folder mounted at `/project`. It resumes the last selected native conversation for that folder. Optional `--new`, `--resume ID` and `--once REQUEST` select startup behavior. Interactive commands include `/new [TITLE]`, `/sessions`, `/resume ID`, `/rename TITLE`, `/history [TEXT]`, `/page EVENT`, `/fork [EVENT]`, `/compact`, `/status`, `/export FILE`, `/import FILE` and `/quit`. The native Compose overlay also requires an existing `NOMO_NATIVE_STATE` directory, alongside the workspace and evidence directories.

For existing Python-era `project.sqlite3` history, use the previous Nomo entry's `/export FILE` to produce `nomo-conversation-1` JSON, then import that file from inside the selected project with the native `/import FILE`. Etas reads the old format directly, copies its messages into a new native conversation and retains the exact original export text as an archive record. The old JSON and SQLite database are not modified. Source IDs, metadata, timestamps and earlier usage remain available in the retained source package. Native imports receive new local event IDs and fresh native-run ledger counters; historical requests and approvals are data, not active permissions.

`/export FILE` writes a `nomo-native-conversation-1` snapshot to a project-relative path after a complete export preview and native Host approval. Both export and import use Etas filesystem/JSON APIs. Import is currently not atomic across its individual archive writes; interrupted import recovery is not yet accepted. The transfer probe uses the old Python store only to generate an authentic old-format fixture, not to implement the native transfer path.

`/history TEXT` searches event content and names without altering the archive. `/page EVENT` reads up to 50 events from that index and reports the next page; the page size is a display choice, not a storage limit. `/fork [EVENT]` creates a separate conversation containing logical events through the selected source event (all events by default), with fresh native-run counters. Retained original import packages stay complete historical attachments and are excluded from model projection. Interrupted fork recovery remains unfinished.

## Remaining scope

1. Native Git status is now accepted: its actual region-root Host result returned to subsequent native inference on official 0.12.1. Accept the remaining unexecuted Git cases, particularly commit, log, branch listing and staged diff, after the round-limit dependency below is fixed.
2. Complete approval acceptance after etas-interpreter#102: commands do prompt before execution, but their Host authority snapshot is stale. Native file writes and snapshots now have operation previews, actual Host approval and journal ownership. Finish the remaining denial/finalization/error outcomes without waiving the audit.
3. Finish recursive navigation, glob/regex search, full public-tool acceptance and retained terminal jobs. Create/write/edit/mkdir/delete/move/batch/undo and explicit rollback now share one native journal; current functional evidence covers the operation kinds, while the approval gate remains open. Named listing, metadata, selected-file literal search and foreground commands are implemented. The current Command API exposes synchronous `run`; retained PTY jobs, input/output handles and restart attachment need a supported native substrate. `examples/native-project/COMMAND_LIFECYCLE_DEPENDENCY.md` records the inspected public APIs and required contract.
4. The native entry owns `nomo>`, user input, continuous model/tool calls and the conversation commands listed above. Remaining: the full product command surface, project switching/recent-project selection and tool shortcuts.
5. Native persistence, selection, normal new-process restore, manual summaries, ledger records, old-format transfer, history search/paging/fork are implemented and accepted in the recorded scopes. Remaining: automatic-threshold/large-context capacity acceptance after etas-interpreter#101, project instructions/configuration, and complete interrupted-operation recovery. Provider usage is not currently exposed to this source ledger.
6. Finish task lifecycle, interruption and recovery decisions in Etas, including generic unfinished commands/models, imports/exports and forks. Completed-file-journal reconciliation and idempotent result finalization are implemented; the two-process result test covers one finalization window. Published partial file work has explicit native rollback and read-only inspection across a new process. Python environment helpers must not retain the product state machine.
7. Switch the official entry only when the complete native product can run. Until then, retain the working current entry and document the prototype separately.
8. Complete continuous dialogue → read → approved edit → check → Git → exit → new-process restore. The complete 0.12.1 attempt is blocked by etas#79: `ModelExecutionPolicy` defaults to eight native tool rounds, and the current CLI/profile does not expose the Rust policy field. The observed ninth request aborts before the remaining operations. Minimal recipe and report: `examples/repros/tool-rounds-0.12.1`, https://github.com/etas-project/etas/issues/79. Increasing token limits does not change this policy, and no workaround is installed.

The migration is incomplete. The accepted native conversation/file/foreground command flows do not establish complete tool coverage, interruption/terminal lifecycle, automatic large-context handling or delivery readiness.
