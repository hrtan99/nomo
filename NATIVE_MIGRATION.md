# Native Etas migration — in progress

The shipping `scripts/nomo` entry still uses the existing Python project controller. The opt-in `native_project` flow is the migration implementation, not a completed replacement.

## Current 0.13.0 acceptance

The current official graph is ETAS 0.13.0 (`config/etas-latest-main.json`), with no source overrides. The official 0.12.1 manifest, lock and isolated cache are preserved. ETAS #79 and interpreter #101/#102 are closed upstream, and their original application-level failures have been rerun rather than waived:

- The unchanged full read/edit/check/all-Git/chat/exit/new-process workflow passes, including the strict command approval authority audit. Fifteen local synthetic model requests.
- The original 2,400,000-byte historical message imports completely and triggers automatic native summarization; the full original remains readable. Two local synthetic requests. This proves this text/history scope, not an actual 1M-token provider capacity.
- Configuration conversion/checks/summary/fresh-process cache also pass in the new cache. The shipping Python-controller entry passes its existing compatibility scenario with 0.13.0; that compatibility result is not native migration evidence.
- New native process tools pass start/read/exact Unicode input/EOF/exit/stop and saved-output restoration. Fourteen individually approved native process actions pass the extended authority audit.
- **Fresh-process live-job reconnection still fails.** The native launcher starts a new Etas Host and the new Host cannot find the old process ID. Saved metadata and output restore; this is not live process reattachment. No detached shell/Python manager is substituted. Native project selection and actual root remounts now pass too; remaining lifetime/configuration and interruption acceptance are listed below before default cutover.

## Launch the native entry

With the existing Docker image and official 0.13.0 toolchain installed, set `MINIMAX_API_KEY` in your shell and run:

```sh
./scripts/nomo-native ~/Projects/nomo-test
./scripts/nomo-native --open
./scripts/nomo-native ~/Projects/nomo-test --new
./scripts/nomo-native ~/Projects/nomo-test --resume native-0
./scripts/nomo-native ~/Projects/nomo-test --once 'List the project files.'
```

The project defaults to the invoking directory when omitted. Install the configuration codec once with `./scripts/nomo-native-tools.sh`. A fresh toolchain installation uses `./scripts/etas-0130-official-container.sh prepare` followed by `build`.

The launcher canonicalizes the project path, prepares private state/trace directories, binds the project as `/project` and directly executes `etas run /workspace --flow native_project --profile nomo-native --allow-effects`. It forwards product arguments to Etas. After Etas selects another folder and writes its reviewed launch request, the shell transports that path to the next mount and starts Etas again; it does not interpret model actions or choose a conversation. Native inference permits 256 tool rounds through the supported `--max-tool-rounds` option; `NOMO_NATIVE_MAX_TOOL_ROUNDS` selects another CLI-supported value (1–4096). Etas owns session selection, commands, model/tool dispatch, history and recovery. The shell does not open or interpret conversation storage. The process runs as the invoking uid/gid, with read access to the existing tool-cache group; compiler/cache mounts stay read-only. State and each run's separate trace directory are created under umask `077`, without relaxing private host directory permissions.

Native state defaults to `${XDG_STATE_HOME:-~/.local/state}/nomo/native`; `NOMO_NATIVE_STATE` selects another location. `NOMO_NATIVE_TRACE_ROOT` selects the parent of the unique per-run trace directories, otherwise `STATE/traces` is used. The launch output prints both paths. This separate native database does not replace Python-era history; use the explicit export/import path below. Inside Nomo, `/help`, `/sessions`, `/resume ID`, `/history`, `/config`, `/check` and `/quit` are native commands. Use `/projects` and `/open [FOLDER_OR_NUMBER]` to select another project. Etas saves recent projects and makes the selection; the launcher canonicalizes/mounts the chosen path and Etas restores that folder's selected conversation. `--open` starts with the native recent-project chooser. Control files are unique to each invocation, so an earlier mount request is not replayed after an unrelated restart.

The native probe invokes the Etas binary directly; Python supplies only a local synthetic HTTP model, terminal transport and fixture setup/assertions.

The `ScopedReplace` trace spec permits reads, listing, atomic replacement and the native command actions needed by the shared journal; it forbids `Fs.write<ProjectRoot>`. The runtime requires human approval for every atomic replacement and command. Snapshots, directory operations and restoration use trusted-unconfined Unix utilities through the checked Command Host, not a Python dispatcher or an unapproved filesystem helper. Each command's actual argv is previewed before its runtime approval. This is not a filesystem compare-and-swap guarantee against external writers.

The earlier 0.12.1 approval gate failed for these command paths; the current 0.13.0 full-workflow and process probes pass the same strict audit. The executed positive flow prompted separately for every command, but its actual CommandRequest/trace omitted the just-obtained approval from the authority snapshot. This was the observed consistency bug etas-interpreter#102, now fixed upstream; it was not evidence of a prompt bypass. The tests retain a fresh-approval audit, comparing the dispatch snapshot with its own preceding approval rather than assuming a global count of one.

File discovery and recursive search execute ripgrep through the existing native Command Host. They use its ignore/glob/regex semantics instead of a Python scanner or a replacement pattern engine. Ordinary discovery honors ignore files, including outside a Git repository; an explicit positive glob has ripgrep's usual override precedence. `.git` and `.nomo` are always excluded. Arguments and patterns are passed as separate argv data. Read-only search and Git status/diff/log/branch listing record observations, so inspecting an unfinished edit does not replace its pending request; native command approval still applies.

Foreground commands can receive one complete UTF-8 stdin value through `run_command_input`. The exact input is archived with argv before dispatch and appears in the full native approval preview. Actual output reaches the next native inference; command/inference attempt completion clears only the matching pending request. This call waits for the process result. The new process tools below add pipe-based background I/O and stopping in the live Host. Durable cross-Host processes and PTYs remain upstream dependencies.

`/tree [PATH]`, `/glob PATTERN` and `/search REGEX` call these same native tools. `/tree` displays files through depth three, omitting empty directories; the agent's `find_files` can select any depth or zero for unlimited traversal. The current Command Host's collected-output bound remains in force.

## Native file journals

All file mutation entry points, including the earlier `replace_file` and `edit_file`, now delegate to `mutations.apply_plan`. Etas owns path checks, missing-parent steps, snapshots, ordered application, result publication, journal selection, undo and explicit rollback. Journal metadata uses a separate native Memory region. Native `cp -a` snapshots live under `/native-state/edits/EDIT/`; binary contents, directory trees and Unix file modes are retained. Conversation export preserves the logical operation history, but does not transfer or activate these local undo backups.

A step's recovery material is stored before project mutation, and its phase changes to `applying` immediately before dispatch. Incomplete/failed work keeps the original conversation's pending request; internal commands record operation/result events under that owner rather than replacing it. A new mutating tool cannot overwrite the pending ticket, and completion must match its owner. Read-only file/navigation inspection records observations without clearing the ticket.

`/edits`, `/read FILE`, `/undo [EDIT]` and `/rollback EDIT` are Etas commands. Rollback walks unfinished steps backward after fresh native approval and never replays the original forward request. A completed batch and undo restored text, binary files, a directory tree and mode `0751`. A separate real Ctrl-C run stopped after a file was published and before its after-snapshot copy was approved; a new Etas process listed the journal, read the actual file without losing the pending ticket, and rolled back the partial batch. That recovery used no additional model request.

`/recover EDIT` and the native `reconcile_changes` tool settle a completed journal without replaying project operations. A previously published complete result is retained when its pending slot is cleared; result publication is idempotent across process restart. Versioned file plans interrupted before journal insertion can be classified as undispatched. Older complete, unjournalled requests retain an unknown outcome. Interrupted undo before journal ownership changes leaves the original edit applied; unfinished claimed journals still require explicit rollback. The reconciliation tool has only native Memory effects.

These are process-restart observations, not proof of every interruption window. Native attempt recovery is described below; remaining interruption windows and retained terminal jobs are not fully accepted. A batch has per-operation approvals and a retained partial state; it does not have a single atomic filesystem commit. The authority audit still fails on upstream #102, so the feature's full approval acceptance is incomplete.

## Native execution attempts

`nomo.native.lifecycle` owns durable attempts for coding inference, summaries, foreground commands, command-based read-only observations and exports. Its separate Memory region retains `prepared`, `dispatching`, `returned`, `completed` and `closed_unknown` stages, input/result event references and a reference to the full archived recovery note. Existing conversation records keep their schema. A stage recorded before a Host boundary does not establish that the Host ran; missing completion does not establish a live process or its termination.

Startup reports unresolved attempts. `/runs` lists them; `/resolve-run ID [NOTE]` is an interactive user command and is not registered as a model tool. If a complete result is already saved, reconciliation keeps that exact event, adopts a saved summary or clears the matching command's pending slot, then finishes metadata without duplicate history or Host calls. If no complete result is saved, a user inspection note is required and the attempt becomes `closed_unknown`. The command's original request stays in history with a separate recovery record; no synthetic success/exit code/tool result is created. File-journal pending requests remain owned by their existing undo/rollback/reconciliation paths.

A new inference requires the prior unresolved inference to be reconciled. Interactive mode explains that the new prompt was not submitted and stays available for inspection/recovery commands. `--once` returns a nonzero status when its prompt cannot be submitted. The program does not automatically resume an interrupted inference, retry a command or infer background-process state. Native runtime errors can still terminate the current process; source-owned records permit an explicit decision in a new process. Retained PTY handles, output polling, input and stop still depend on the native Command lifecycle substrate described below.

The executed positive flow approved one exact foreground command, observed its synthetic file marker, interrupted it with Ctrl-C, then opened a new Etas process. Native file inspection retained the command's pending ticket. User resolution closed command and inference attempts with unknown outcomes, a new user turn completed, and recovery dispatched no command. Two-process metadata fixtures separately retained saved coding/summary/command results and finalized their pointers/pending slots without duplicating events. This does not establish every interruption window, concurrent recovery or automatic inference continuation. The command approval audit still fails on upstream #102.

## Native conversations and context

`ConversationStore` / `NativeHistory` use the Etas Memory Host with SQLite at `/native-state/conversations.sqlite3`. Etas owns session creation, selection, listing, renaming, user/assistant messages, tool requests/results, summaries and the ledger. A source `SessionContext` effect binds tool logging to the selected conversation; the entry handles it inside the model call. There is no Python conversation or SQLite adapter in this path.

Events are append-only records with separate content chunks. The 65,536-scalar chunk width keeps individual Memory values below the upstream storage limit; it is not a task, message or conversation length limit. Large-event acceptance is blocked by the native string-slice continuation hang reported in etas-interpreter#101; no slicing workaround is used. Event indexes are reserved before publication. An interrupted archive write appears as an explicit incomplete record, and a tool is not dispatched until its request record is saved. Pending requests survive process exit and are shown on startup; complete interruption/recovery handling remains a separate unfinished gate.

`RollingContext` keeps the original request, a model-generated summary and recent original events. After summarization, the recent suffix uses configured `keep_messages` (default 12), subject to 393,216 text bytes and available context; larger events remain in the archive and are represented by the summary. The current 0.13.0 large-event import/automatic-compaction scenario passes; the old #101 failure remains in historical evidence. The automatic trigger uses a text estimate of three UTF-8 bytes per token at 75% of the configured 1,048,576-token window. `/compact` uses the native summary agent; it never deletes original events. The ledger records attempted agent turns, tool requests, compactions, configured generation allowances and estimated context bytes. These counters are not measured provider token usage or billing.

Each native turn loads the current root `AGENTS.md` through native filesystem APIs. `project_instructions(FILE)` discovers applicable guides from root to the file's parent; missing future directories leave existing ancestor guidance available. `read_file` includes those guides with the actual file content. The coding agent is instructed to obtain scoped guidance before preparing changes to an uninspected path, including move destinations. Guide contents and historical approval records do not grant Host permission. The native project configuration layer below loads `.nomo.toml`; arbitrary per-call runtime limits and retained terminal timing remain unfinished.

The native entry requires `--workspace PATH` identifying the folder mounted at `/project`. It resumes the last selected native conversation for that folder. Optional `--new`, `--resume ID` and `--once REQUEST` select startup behavior. Interactive commands include `/new [TITLE]`, `/sessions`, `/resume ID`, `/rename TITLE`, `/history [TEXT]`, `/page EVENT`, `/fork [EVENT]`, `/compact`, `/status`, `/export FILE`, `/import FILE` and `/quit`. The native Compose overlay also requires an existing `NOMO_NATIVE_STATE` directory, alongside the workspace and evidence directories.

For existing Python-era `project.sqlite3` history, use the previous Nomo entry's `/export FILE` to produce `nomo-conversation-1` JSON, then import that file from inside the selected project with the native `/import FILE`. Etas reads the old format directly, copies its messages into a new native conversation and retains the exact original export text as an archive record. The old JSON and SQLite database are not modified. Source IDs, metadata, timestamps and earlier usage remain available in the retained source package. Native imports receive new local event IDs and fresh native-run ledger counters; historical requests and approvals are data, not active permissions.

`/export FILE` writes a `nomo-native-conversation-1` snapshot to a project-relative path after a complete export preview and native Host approval. Both export and import use Etas filesystem/JSON APIs. New exports retain conversation, attempt and copy metadata in the versioned `nomo-native-metadata-1` JSON string inside the existing portable format. Import preserves that exact source package as historical data; earlier attempts and approvals are not activated in the new conversation. Import writes events incrementally into an unselected conversation copy. A durable native copy job is saved before its session, and the existing selected conversation remains active until the entire copy is published. The retained source package is bound to a native SHA-256 digest; once sealed, recovery reads that saved package even when its original filename is gone. If archiving the package itself was interrupted, resume repairs its deterministic historical slot using the matching original file. No project tool or old approval is replayed. A source already complete before its phase update can also be recovered from the saved package. The transfer probe uses the old Python store only to generate an authentic old-format fixture, not to implement the native transfer path.

`/history TEXT` searches event content and names without altering the archive. `/page EVENT` reads up to 50 events from that index and reports the next page; the page size is a display choice, not a storage limit. `/fork [EVENT]` creates a separate conversation containing logical events through the selected source event (all events by default), with fresh native-run counters. Retained original import packages stay complete historical attachments and are excluded from model projection. Forks use the same durable copy cursor and publish-after-completion mechanism. Source records through the chosen boundary must be complete; new source events are outside the captured boundary. Normal fork execution and new-process restoration are accepted; a separate fork Ctrl-C run has not been performed.

`/copies` lists native import/fork jobs with their phase and progress. Startup reports unfinished jobs without selecting them. `/resume-copy ID` continues the same copy, filling an incomplete reserved historical slot or skipping an already complete one; `/discard-copy ID` marks an unfinished copy discarded while retaining its original and copied records. Incomplete or discarded copies cannot be selected for ordinary dialogue. The live conversation archive still exposes interrupted reservations rather than replaying them; deterministic repair is confined to unpublished copy jobs. These jobs use a separate Memory region, preserving the existing conversation schema. This protocol does not automatically classify or repair partial imports created before copy journalling existed.

## Native project configuration

Run `./scripts/nomo-native-tools.sh` once to install fixed Taplo 0.10.0 in an isolated tool directory; the existing Nomo image already supplies jq. `configuration.es` reads `.nomo.toml` through native filesystem APIs. Generic native Command Host calls convert exact stdin from TOML to JSON, then into typed key/value-entry arrays. The codecs contain no Nomo keys or policy. Etas selects fields, applies defaults, validates values and owns all resulting behavior. Optional `[project]`, omitted fields, unrelated keys, multiline strings and Unicode are retained. This uses the supported data representation; no compiler patch or weakened record validation is introduced.

The parsed cache binds a native SHA-256 of the actual input to its complete archived codec result. Unchanged content, including after a fresh process, repeats no decoder process or approval. Changed content is decoded again. Configuration instructions accompany scoped project guidance; native recursive discovery/search apply extra ignore globs; `check_project` and `/check` execute the configured argv with actual Host approval. Common `python3`, `git` and `sh` program aliases resolve to their configured absolute allowlisted programs.

`context_window` and `compact_ratio` govern text-estimate projection/admission; `keep_messages` controls the recent suffix subject to available bytes. `/config` distinguishes the estimated per-request context window from the cumulative inference token allowance and per-request output cap. The coding inference allowance is 536,870,912 input-plus-output tokens; its output cap remains 131,072 per HTTP request. The summary inference allowance is 1,048,576 tokens with a 32,768 output cap. Arbitrary requested `max_output_tokens` values still need a native per-call API; the current coding entry explicitly does not submit a model request for a different output allowance. `command_timeout` is retained but reported inactive; the current source does not apply it as a per-command timer. These are partial runtime configuration capabilities, not full acceptance of every setting. Contract and dependencies: `examples/native-project/CONFIGURATION_DEPENDENCIES.md`.

## Native background processes

`processes.es` owns saved job metadata, per-conversation ownership, exact operation previews, command attempts, result publication and native output storage. The registered tools are:

| Tool | Parameters / return | Native effect / approval |
|---|---|---|
| `start_job` | `program`, `arguments`; `Job {id, session, program, arguments, handle, phase}` | `Command.start<DefaultCommandSandbox>`; exact argv and native approval |
| `read_job` | `job`, `max_bytes: usize`; `JobEvent` | Fresh `Command.reconnect` and `Command.read` approvals; waits for output or termination |
| `write_job` | `job`, `input`; `{job, operation, status}` | Fresh reconnect and `Command.write` approvals; exact UTF-8 input, no added newline |
| `close_job_input` | `job`; `{job, operation, status}` | Fresh reconnect and `Command.write` approvals; closes stdin |
| `stop_job` | `job`; `JobEvent` | Fresh reconnect and `Command.stop` approvals; actual Host terminal event |
| `list_jobs` | no arguments; `Array<Job>` | Native Memory; phases are last observations, not current liveness |
| `job_output` | `job`; `Array<JobEvent>` | Native Memory/history; reads saved events without consuming Host output |

`JobEvent` contains the job ID, input-event reference, phase (`output`, `exited`, `stopped`), `Option<i32>` exit status, display stdout/stderr and original byte arrays. Original bytes remain intact even if a bounded read splits a UTF-8 sequence; display text uses replacement decoding. Output is saved in the native process Memory region and conversation archive. Imports preserve historical event data without activating old process handles. An interrupted Host/read publication may have an uncertain result; metadata does not manufacture completion and the request is not replayed.

The native command loop also supports:

```text
/exec ["/usr/bin/git","status","--short"]
/spawn ["/usr/bin/python3","-u","-c","import sys; print('ready',flush=True); print(sys.stdin.readline(),flush=True)"]
/jobs
/poll JOB 65536
/send JOB "hello\n"
/close-input JOB
/stop JOB
/job-output JOB
```

`/exec` and `/spawn` take JSON argv arrays rather than interpreting a shell command line; `/send` takes a JSON string and adds no newline. `/poll` consumes the next Host output event and waits if no output or terminal status is available. Use `/job-output` to revisit retained output. Native Host unread-output limits still apply. A stopped job has no invented exit code. Saved output restores after exit; live process reconnection across a fresh Host is explicitly not accepted.
